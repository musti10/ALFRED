# 0.16.0 — Conversation reliability

## Changes

- Browser and iPhone require roughly 300 ms of continuous above-threshold audio before accepting speech. Scattered short noise bursts no longer accumulate into a confirmed turn.
- The end-of-turn silence allowance increases from 1.4 to 2 seconds, preserving longer clause pauses at the cost of about 0.6 seconds of additional end-of-turn waiting.
- Both clients retain no-speech timeouts and explicit recording limits. Manual browser dictation remains manual.
- Transcription, chat, and other mutating requests now respect active synthesis, closing the asymmetric inference guard. State reports synthesis as busy; cancellation releases that state.
- Temporary iOS system dialogs no longer end a conversation solely because the scene becomes inactive. Backgrounding and audio interruptions still stop it.

## Verification

20 backend tests and 8 native/Swift tests passed locally. The actual Swift detector and browser detector consume the same timing/noise fixtures, covering silence, scattered spikes, a 1.8-second clause pause followed by more speech, a short burst, a delayed meter sample, and maximum turn duration. A route-level test verifies synthesis excludes transcription/chat and cancellation restores availability.

This is still energy-based detection, not semantic VAD. Real microphone, noise, and end-to-end quality comparisons remain necessary. No new voice model, weather tool, document access, or autonomous capability is introduced by this release.
